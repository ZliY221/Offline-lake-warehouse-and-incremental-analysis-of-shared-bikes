# 学习单元 02：Silver 质量规则、去重与拒绝数据

## 为什么不能只做 `dropDuplicates`

`dropDuplicates(["trip_id"])` 会任意保留一条同主键记录。如果两条记录完全一致，这通常只是重复投递；如果距离、时间或站点不同，则是主键冲突，任意保留会把不可解释的数据送进指标层。

本项目先计算业务字段 SHA-256 指纹，再按 `trip_id` 分组：

- 同一 ID、同一指纹：保留一条，其余标记为 `exact_duplicate`；
- 同一 ID、不同指纹：不选“赢家”，全部标记为 `conflicting_duplicate`；
- 无重复且通过规则：进入合法 Silver 数据集。

## 质量规则

当前规则覆盖 JSON 损坏、必填字段、ID 格式、时间顺序、最长四小时、站点集合、起终站相同、骑行者类型、车辆类型和距离范围。单条记录可以保存多个错误码，便于发现连锁问题，而不是只暴露第一项错误。

## 最小披露拒绝记录

损坏的原始 JSON 可能包含意外敏感内容。拒绝数据集删除 `_corrupt_record`，只保存：

- 原始内容或规范化业务字段的 SHA-256 指纹；
- 损坏载荷的 UTF-8 字节数；
- 来源文件、摄取日期和错误码；
- 能够按显式 Schema 解析出的非敏感业务字段。

这既支持问题计数和重放定位，也避免直接复制未知原文。

## 重建与幂等

当前 Silver 作业读取完整 Bronze 数据集并完整重建三类输出，因此相同 Bronze 输入重复执行时，合法、拒绝和重复记录的数量与内容保持一致。后续加入批次清单后，再演进为受控的分区增量重建。

## 可复现实验

执行：

```powershell
./scripts/silver-quality-demo.ps1
```

固定输入包含 12 行：1 条合法记录、8 条业务或结构拒绝记录、1 条精确重复和 2 条冲突重复。脚本先构建独立 Demo Bronze，再输出三类 Silver Parquet 数据集。
