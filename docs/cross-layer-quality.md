# 跨层质量守恒与机器可读报告

## 为什么单层行数不够

每个作业都“成功退出”不代表指标正确。数据可能在层间被静默丢弃、维度可能出现多个当前版本、Gold 也可能因为关联错误而少算。质量报告应检查跨层不变量，而不只是分别展示几张表的行数。

## 六项核心检查

1. Bronze 总行数等于 Silver 合法、拒绝和重复行数之和；
2. 每个站点恰好有一个 `is_current = true` 版本；
3. 每个站点相邻 SCD2 版本首尾相接，最后版本无结束日期，当前标记与结束日期一致；
4. Gold 日指标中的 `trip_count` 总和等于合法 Silver 行程数；
5. 热门路线排名位于配置范围内，同一日期和行政区内没有重复名次。
6. Cohort 留存人数不超过 cohort 规模，留存率位于 0—1，第 0 天人数等于 cohort 规模且留存率为 1。

这些检查覆盖了分流、维度历史、事实聚合、窗口排名和 cohort 计算五类常见故障。

## 质量问题不等于作业失败

Silver 拒绝和重复记录可以是预期的数据质量结果，因此报告展示错误码和重复类型分布，但不因数量非零直接失败。真正违反行数守恒或模型约束时才标记 `FAIL`。如果历史控制清单中存在失败批次而当前数据不变量正常，则总体状态为 `WARN`。

## 可复现实验

```powershell
./scripts/build-quality-report.ps1
```

输出是机器可读 JSON，包含总体状态、数据集行数、Bronze 分区行数、质量分布、批次状态汇总和每项检查证据。固定正式样例为 20 行 Bronze、20 行合法 Silver、11 个站点历史版本、10 行日指标、9 行热门路线和 1 行 cohort 留存，六项检查全部通过。
