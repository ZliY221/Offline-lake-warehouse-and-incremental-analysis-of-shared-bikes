# Gold 时态关联、日指标与热门路线

## 时态维度关联

如果所有历史行程都关联 `is_current = true` 的站点记录，站点改名、调整行政区后，过去的指标也会被新属性重写。Gold 使用行程的 `business_date` 做时态关联：

```text
business_date >= valid_from
AND (business_date < valid_to OR valid_to IS NULL)
```

这与 SCD2 的左闭右开有效期一致，使历史事实始终匹配当时有效的站点版本。

## 完整性保护

作业分别关联起点与终点站点维度。关联后会统计未命中的起点和终点；只要存在未命中记录，作业就抛出错误，不写出不完整指标。这样可以把维度缺口暴露为数据质量问题，避免内连接静默丢行导致指标偏小。

## 日指标粒度

`daily_metrics` 的唯一粒度为：

```text
business_date + district + rider_type + bike_type
```

其中 `district` 来自当日有效的起点站点版本。指标包括行程数、总骑行分钟数、平均骑行分钟数和总距离；时长与距离显式转换为两位小数的 Decimal，避免浮点累计误差影响验收。

## 分组 Top N 路线

路线先按日期、起点行政区、起点站和终点站聚合，再在每个 `business_date + district` 分组内按行程数降序排名。行程数相同时按起终站 ID 升序打破并列，保证重复运行结果稳定。默认只保留每组 Top 3，可通过脚本参数调整。

## 可复现实验

先完成 Bronze、Silver 和站点维度构建，再执行：

```powershell
./scripts/build-gold.ps1
```

固定 20 条正常样例生成 10 行日指标和 9 行热门路线。自动化测试另用 5 条可手算行程验证计数、总和、平均值、距离、排名，以及站点在第二天切换行政区后指标归属随历史版本变化。
