# 站点快照与 SCD2 历史维度

## 为什么需要 SCD2

如果直接覆盖站点表，容量调整、改名或停用之后就无法解释历史行程当时对应的站点属性。缓慢变化维第二型（SCD Type 2）为每次属性变化保留一个版本，使事实数据能够按发生日期关联到当时有效的维度记录。

本项目跟踪站点名称、行政区、容量和启用状态。只有这些字段发生变化才创建新版本，连续两天完全相同的快照不会制造冗余历史。

## 有效期约定

每个版本使用左闭右开区间 `[valid_from, valid_to)`：

- `business_date >= valid_from`；
- `business_date < valid_to`；
- 当前版本的 `valid_to` 为 `null`，同时 `is_current = true`。

左闭右开能让前一版本在变化日自动失效、新版本在变化日立即生效，避免两个版本同时命中同一日期。

## 重复与冲突处理

作业按 `station_id + snapshot_date` 分组并计算业务字段指纹：

- 指纹完全相同：保留一条，其余计为精确重复；
- 同一站点同一天出现不同指纹：全部进入拒绝数据，错误码为 `CONFLICTING_STATION_SNAPSHOT`；
- 字段缺失、格式非法或容量非正数：进入拒绝数据并保留明确错误码。

冲突记录不选择“赢家”，避免把不确定的站点状态写进历史维度。损坏原文同样不落盘，只保留 SHA-256 指纹和字节数。

## 全量快照的边界

当前输入约定为每日全量快照。站点停用必须显式写入 `active = false`；仅仅在后一天缺少某个站点，不能推断它已经停用，因为缺失也可能来自上游漏数。

当前实现采用全量重建，保证相同输入重复运行得到相同历史。维度规模较小且不按布尔 `is_current` 分区，避免部分读取器把路径分区值恢复为字符串而破坏字段类型。

## 可复现实验

执行：

```powershell
./scripts/build-station-dimension.ps1
```

固定两日样例共 16 条快照。第二天有三个站点属性变化，因此 8 个站点最终生成 11 个历史版本，其中 8 个是当前版本。自动化测试还覆盖连续有效期、精确重复、冲突快照、非法容量和损坏 JSON。
