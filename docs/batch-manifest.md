# 批次清单、文件指纹与运行状态

## 批次控制信息

只有 Parquet 输出时，很难回答“哪一个源文件在什么时候处理过、是否重跑、输入输出行数是否一致、失败发生在哪一步”。批次清单把运行元数据与业务数据分开保存，使摄取过程可以审计和排错。

## 确定性批次 ID

Bronze 在读取前流式计算来源文件的 SHA-256 和字节数，批次 ID 由以下内容组成：

```text
trip-bronze-{ingestion_date}-{source_sha256 前 16 位}
```

相同日期、相同内容会得到相同批次 ID。文件改名但内容不变不会改变数据身份；内容发生一个字节变化则会得到不同指纹。

## 状态机与原子写入

开始处理时先写 `RUNNING`，成功后更新为 `SUCCEEDED` 并记录行数，异常时更新为 `FAILED` 并保存异常类型和截断后的错误消息。每次都先写同目录临时文件，再用文件替换完成提交，避免读到半份 JSON。

同一批次重跑不会追加重复记录，而是更新同一个文件并增加 `attempt_count`。这样既能表达幂等身份，也能看出实际尝试次数。

## 当前记录字段

- 批次 ID、管道名和摄取日期；
- 来源文件名、SHA-256 与字节数；
- 输入行数、损坏行数和目标分区行数；
- 尝试次数、UTC 开始/完成时间和状态；
- 失败时的异常类型与有限长度错误消息。

## 可复现实验

连续执行两次：

```powershell
./scripts/build-bronze.ps1
./scripts/build-bronze.ps1
```

固定 20 行样例的批次 ID 保持不变，目标分区仍为 20 行，清单目录只有一个对应 JSON，`attempt_count` 从 1 变为 2。
