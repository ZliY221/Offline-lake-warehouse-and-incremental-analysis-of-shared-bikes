# 需求与验收标准

## 目标

构建一个可在单机环境和 CI 中复现的 PySpark 离线湖仓，使用合成共享单车数据验证批次摄取、分层建模、维度历史、增量处理、数据质量和 SQL 分析。

## 数据集

### 行程事件

粒度：一行代表一次完整行程。

字段：行程 ID、纯合成匿名骑行者键、开始/结束时间、起终站点、骑行者类型、车辆类型、距离。匿名键不得由真实个人信息生成或与真人建立映射；不得包含姓名、电话、证件、支付标识或精确轨迹。

### 站点快照

粒度：一行代表某个快照日期上的一个站点状态。

字段：快照日期、站点 ID、名称、行政区、容量和启用状态。后续使用每日快照构建 SCD2。

## 分层要求

- Bronze：显式 Schema 读取，保存来源文件、摄取日期和原始字段，按摄取日期分区。
- Silver：校验业务规则，隔离拒绝记录，按 `trip_id` 去重，派生骑行分钟数和业务日期。
- DIM：根据站点快照维护有效开始、有效结束和当前标记。
- Gold：按日期、行政区、骑行者类型和车辆类型统计行程数、总时长、平均时长和热门路线，并按匿名骑行者首次骑行日计算 cohort 留存。

## 增量要求

- 同一摄取日期重跑不得重复追加数据。
- 更新某一日期分区不得删除其他日期分区。
- 输入清单应记录批次、文件哈希、行数和状态。
- 回填历史日期时必须明确影响的分区和指标。

当前批次清单与单日期回填已实现。回填在写入前验证业务日期和跨摄取分区 `trip_id` 隔离约束，只替换目标 Bronze/Silver 分区以及目标业务日期的 Gold 日指标和热门路线分区。Cohort 会根据受影响骑行者改写前后的首次活动日推导旧、新 cohort 日期，只替换这些分区；计算仍扫描完整 Silver。控制记录分别保存影响范围和计算范围。

## 验收标准

1. 相同生成参数得到完全相同的输入文件。
2. Spark 使用显式字段类型，不依赖生产输入的自动推断。
3. Bronze Parquet 按 `ingestion_date` 分区。
4. 同日重跑行数不翻倍，另一日期分区保持不变。
5. Silver 能区分合法、重复和至少五类业务失败。
6. 站点属性变化产生不重叠的 SCD2 有效期。
7. Gold 指标可由小样本手工核对。
8. 所有性能数字具有环境、输入、方法和原始逐轮结果。
9. Cohort 留存使用合成匿名键，且可由小样本手工核对第 0 天和跨日留存。
10. 单日期回填不得重写无关 Silver、日指标和路线分区；跨分区主键冲突必须在 Bronze 写入前失败。
11. 骑行者因历史回填改变 cohort 归属时，旧、新 cohort 分区都必须重算，其他 cohort 分区不得改写。
12. 相同聚合在 Sort-Merge Join 与显式 Broadcast Hash Join 下结果必须一致，并保存可核验的格式化物理计划与 AQE 启用证据。
13. AQE 证据必须来自 action 后的最终计划；受控热点键场景必须观察到分区合并和倾斜 Join 标记，且启用前后聚合结果一致。
14. 受控 Spark 作业必须通过实时 `/api/v1` 保存所属 Job、完成 Stage 和任务指标，并核对输入总行数、Shuffle 读写、任务数与 Spill。
15. 全链路编排必须显式校验依赖图，为每次尝试保存退出码和日志哈希；失败任务可在限定次数内重试，恢复运行不得重跑已成功任务。
16. Airflow DAG 必须复用同一五阶段任务定义，远程 CI 验证导入、依赖和重试配置；本机完整 DAG 必须观察到受控失败、原生重试、下游依赖阻塞和最终质量门禁成功。
17. Airflow 日期回填必须接收类型化目标日期与受限输入路径参数；有效请求应在原生重试后通过质量门禁，无效日期请求应耗尽重试、写入最小化失败审计，且不得改变 Bronze 文件。

当前第 1—17 项均已完成。性能结论随仓库保存环境、输入、方法和三轮原始结果；物理计划、UI REST、本地编排和 Airflow `DAG.test()` 只证明受控单机行为，不表述为生产集群或生产调度运维能力。日期回填回调只落本地最小化 JSONL，不等同于生产告警、权限审批或并发补数治理。
